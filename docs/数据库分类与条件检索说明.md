# Spin Space Group Database — User Guide

This guide describes the offline desktop application, its classification fields, and how searches are evaluated. The macOS and Windows applications use the same SQLite database and search logic.

## Contents of the database

The catalogue contains **67,475 SSG entries** for 230 parent space groups: 1,421 collinear (L), 9,542 coplanar (P), and 56,512 noncoplanar (N). Of these entries, 8,520 are continuous families. The database also stores 206,288 orbit representations for searches involving equivalent representatives and wavevectors.

An entry is a catalogue class or a continuous family, not a list of all its individual matrices. A continuous-family record covers the allowed general domain; excluded special points are classified separately. The existing Xiao identifiers and catalogue are retained.

**Scope of the classification:** continuous fifth-level profiles preserve exact symbolic data. A proof that all distinct parameterizations have been globally merged into a minimal set is not currently available. The number of fifth-level nodes must therefore not be presented as a proven minimum. Continuous-family equivalence is also not the same as equality of two fixed matrices under one coordinate transformation.

## Five-level classification

The Browse tab organizes entries by the following levels. The hierarchy and the 17 type labels belong to this project; they are not imported from another database's classification scheme.

| Level | Field | Meaning |
| --- | --- | --- |
| 1 | Parent space group | Ordinary crystal space group, with a fixed Hall setting and coordinates. |
| 2 | Configuration | Collinear (L), coplanar (P), or noncoplanar (N). |
| 3 | Spin-lattice type | One of the project's 17 labels describing translation-image and grading structure. |
| 4 | Spin Bravais lattice | Translation and spin structure, displayed using a wavevector representative. This is distinct from the 14 ordinary Bravais lattices. |
| 5 | Spin crystal class | Data including the embedding of H in K under the preceding conditions. |

The leaves below level 5 are individual SSG catalogue entries. A level-3 type, a level-5 node, and a complete Xiao ID are different things: one type can contain multiple nodes and entries.

The 17 level-3 labels are:

- Collinear: L.0.1 and L.0.2.
- Coplanar: P.0, P.1.1, P.1.2, P.2.1, and P.2.2.
- Noncoplanar: N.0.1, N.0.2, N.1.1 through N.1.5, and N.2.1 through N.2.3.

Their exact computational criteria are defined in `ssg_enumeration/labels.py`. For example, P.1.2 is a coplanar Type 1 general-wavevector layer, not a parent-group or Xiao number. A displayed level-4 wavevector is a representative of a stored node; its display alone is not a proof that the notation is globally unique.

## Names and symbols

**SSG name** is the mathematical name in the project's fixed setting and naming convention. It combines the parent Hermann–Mauguin symbol with the required translation wavevectors and spin superscripts. Long names can be scrolled horizontally; all names use the same base formula size. A superscript or subscript is naturally smaller than the main symbol.

**Xiao ID**, for example `L5.2.2` or `P27.5.2`, identifies an entry in the existing correspondence catalogue. It is not the level-3 type: L5.2.2 has type L.0.2.

In a name, a spin superscript such as `2_z` denotes a half-turn about the spin z axis; `m_z` denotes a reflection with normal along z; an overbar on 1 denotes the sign-reversing operation in the relevant effective representation. The naming convention removes the phase attributable to a fractional spatial translation from the displayed point-operation superscript. The group-operation table restores the actual operation and displays its translation. The suffixes for the spin-only symmetry of collinear or coplanar configurations are part of the name; H and K below use the effective representation rather than multiplying in that spin-only group.

`kχ` is the translation grading wavevector. `k₁`, `k₂`, and `k₃` describe rotational translation images; for discrete Type 2 they come from the sign characters of the translation matrices. The rotational wavevectors are matched as an unordered set; `kχ` is a separate field.

Inputs use **conventional reciprocal coordinates**, such as `0,0,1/2`, in the fixed setting. If the primitive basis is `Aₚ = A Cᵦ`, the code converts an input `k` to `q = Cᵦᵀk` and performs exact rational arithmetic modulo the primitive reciprocal lattice. Do not assume each conventional-coordinate component is independently periodic modulo 1. The basis matrix is available in the exported JSON.

For a parent group G, translations T, parent point group P = G/T and effective spin representation ϱ (with ϱ = χρ in the noncoplanar convention):

- `H = ϱT(T)` is the translation image and a normal subgroup of K.
- `K = ϱ(G)` is the effective spin image of the full group.
- `Q = K/H = ϱP(P)` is the point-group image after quotienting out H.
- `ker ϱP` is the set of parent point operations whose representatives have spin image in H.

For finite cases, the catalogue checks `|K| = |H||Q|` and `|P| = |ker ϱP||Q|`. Level 5 retains the embedding of H in K, not merely the abstract name of Q. Continuous families use exact symbolic profiles subject to the limitation above.

## Workspace and navigation

The left sidebar provides **Browse** and **Search**; the results occupy the right side. **Settings** in the application menu controls the count column and automatic expansion depth.

1. In **Browse**, expand the five-level tree or select a node to list its entries. Configurations appear in the order collinear, coplanar, noncoplanar.
2. In **Search**, the independent **Label search** is at the top. The separate **Condition search** below contains the space group, configuration, wavevectors, Q/K, and kernel fields.
3. Applied conditions appear as removable chips above the results. Selecting a chip's × removes that condition and runs the remaining query. Click **Details** on a row or double-click it to open that entry in a separate window.
4. Use **Previous** and **Next** for result pages. **Export results** exports all matching pages, not just the page on screen.

The columns are Configuration, Spin-lattice type, SSG name, Q, K, Xiao ID, Parameters, and Details. The Parameters column distinguishes discrete records, continuous families and concrete matched values.

## Group details

The detail window has Classification and Group operations tabs. You may copy the name as LaTeX or export the selected entry as JSON.

The operations table begins with the three primitive translation generators, T1–T3, followed by one spatial representative for every point operation of the parent space group. Every such representative is shown, including those with the same spin matrix. Together with the translations, these representatives describe the complete space group; the table does not attempt to list its infinitely many translated elements or enumerate representatives of the spin image K. Each row gives the spin matrix, spatial rotation, translation and operation symbols.

For a continuous family the matrices are initially symbolic. The parameter controls evaluate these same rows without enumerating the spin image, which can be infinite. The classification fields retain their catalogue values; evaluating matrices does not recalculate K, Q, or the kernel.

When a joint search returns a concrete matched representative, the group-operation table uses that representative and its own spin frame. Its parameters may differ from the canonical parameters in the displayed name. Manually entering values in **Group operations** uses the name's canonical parameterization; **Reset** returns to symbolic matrices in that frame.

## Search fields

The independent Label search performs a substring match against stored identifiers, Xiao IDs and names. A short string can return multiple entries. It is not a parser for all mathematically equivalent names and is not combined automatically with the lower search fields.

All populated fields in the combined search must hold simultaneously:

| Field | Input and behavior |
| --- | --- |
| Parent space group | Select 1–230. Bravais lattice and crystallographic point group are then set and locked. |
| Bravais lattice | For example `oP` or `mC`. Required before entering any wavevector. |
| Crystallographic point group | Parent crystal point group, not K or Q. |
| Configuration | Collinear, coplanar, or noncoplanar. The type list is restricted accordingly. |
| Spin-lattice type | Exact level-3 label, for example `P.1.2`. |
| Parameter type | Continuous families or discrete entries; this filters catalogue records. |
| kχ | Three rational conventional reciprocal components, e.g. `0,0,1/2`. |
| k₁, k₂, k₃ | Three rational components per field. Multiple rotational wavevectors are unordered. |
| Q = ϱP(P) | Image modulo H, for example `C2`. Without a concrete rotational wavevector, a continuous family's stored general value is used. |
| K = ϱ(G) | Effective spin image; this filter returns discrete catalogue entries only. |
| ker ϱP | Match the abstract kernel group. Equal abstract groups may have different embeddings. |

Use exact fractions such as `1/3` rather than decimal approximations. To look up the fixed point-operation indices, export the entry as JSON.

### Examples

**Find an entry:** enter `L5.2.2` in Label search, search, and select the result. Its parent is 5 (C 2, Hall 9), configuration is collinear, type is L.0.2, grading wavevector is `kχ=(0,0,1/2)`, and H/K/Q are C2/C2/1.

**Filter by parent and type:** select parent 27 (P c c 2), configuration Coplanar, and type P.1.2. Bravais `oP` and point group `mm2` are set by the parent. Without a rotational wavevector the Q/kernel values are the stored general-family values; the K filter is restricted to discrete entries.

**Joint wavevector and quotient search:** with the preceding parent and type, enter `k₁=0,0,1/3` and select `Q=C2`. The current database returns `P27.5.1` and `P27.5.2`. With the same conditions and `Q=C2 × C2`, it returns no entries. The general Q of P27.5.2 is C2 × C2, but the compatible branch for this wavevector has Q=C2. Classification details show the concrete matching evidence; general catalogue fields remain general-family values.

## How combined search is evaluated

1. Validate the inputs and filter fixed fields in SQLite.
2. Convert wavevectors to primitive coordinates and check the stored orbit representatives with exact modulo-integer equations. Continuous-family membership is checked in its parameter domain, excluding special points; floating-point sampling is not used.
3. If no rotational wavevector is combined with Q, K, or kernel conditions, compare those group fields against the stored general or discrete value. K filters restrict the desktop search to discrete entries.
4. If at least one of k₁/k₂/k₃ is combined with Q, K, or kernel conditions, solve for compatible parameter lifts across stored orbit charts, including allowed signs. Evaluate all group conditions on the same compatible representative and attach matching evidence. If unresolved free phases prevent a complete determination, the program reports an error instead of substituting samples.
5. Count each matching classification once, even if several representatives match. Pagination does not alter the total; exporting iterates through all pages.

Only k₁/k₂/k₃ trigger the joint specialization in step 4. A search using only kχ with Q/K/kernel matches the grading wavevector but uses the stored general image. Special rational parameters can change the image or kernel.

## Continuous parameters and troubleshooting

For a continuous family, enter the canonical parameters `u₀,u₁,…` in **Group operations**, for example `1/7` or `1/7,2/11`, then select **Calculate**. Fractions with denominators up to 48 are displayed exactly. Decimal values, larger-denominator fractions, and expressions such as `sqrt(2)/10` or `pi/10` are evaluated numerically, and the result is marked approximate. **Reset** restores symbolic matrices. Special values can belong to a separately classified record; numerical matrix evaluation alone does not determine that classification. These parameter controls are separate from the exact rational wavevector fields in condition search.

- **Wavevector fields are disabled:** first choose a Bravais lattice, or choose a parent space group to set it automatically.
- **Same Q, different level-5 nodes:** the embedding of H in K can differ even when the abstract quotient is the same.
- **General Q differs from matched Q:** a compatible rational parameter can change the image. Check the matched evidence and the catalogue value separately.
- **The name is clipped:** scroll horizontally or adjust the result column. Formula size is not reduced to fit the column.
- **No results:** reset and add conditions one at a time; check coordinate setting, exact fractions and excluded special points.

## Launching and Python access

On macOS, open `Spin Space Group Database.app`. On Windows, extract the entire application folder and open `Spin Space Group Database.exe`; retain the `_internal` folder. The installed application includes its database and requires no network, Python, or TeX at runtime.

From source:

```bash
python -m pip install /path/to/ssg_enumeration-0.9.17-py3-none-any.whl '.[desktop]'
python run_desktop.py --database output/retrieval/SSGclassify.sqlite
```

Python search example:

```python
from ssg_database import SearchDatabase

db = SearchDatabase('output/retrieval/SSGclassify.sqlite')
try:
    results = db.search({'parent': 27, 'bravais': 'oP',
                         'category': 'P.1.2', 'k1': '0,0,1/3',
                         'q_name': 'C2'})
    for row in results['rows']:
        print(row['xiao'], row.get('matched_specialization'))
finally:
    db.close()
```

The database is read-only in the application; exported files are written only to a user-selected location.

The compact database stores the same precompiled vector formulae in blocks of up to 64 names. The application reads both the compact and previous database formats. To make a compact copy of an older database from Python, use:

```python
from ssg_database import compact_formula_database
report = compact_formula_database('old.sqlite', 'compact.sqlite')
print(report)
```

The source is preserved and the destination must not already exist. The compact format needs version 0.9.4 or later; earlier releases cannot read its formula blocks.
